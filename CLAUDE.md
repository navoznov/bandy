## Что это

3D-игра от первого лица в браузере. Игрок ходит по лабиринту комнат, открывает двери,
подбирает предметы, применяет предмет на предмет (ключ на замок) и ищет выход — дверь
с надписью EXIT, за которой длинный коридор с белым светом в конце.
Референс по духу — Hello Neighbor, но антагониста в первой версии нет.

Обязательное требование: играбельно и с десктопа (мышь + WASD), и с телефона (тач).

## Стек

Three.js + TypeScript + Vite, тесты на Vitest, хостинг на GitHub Pages.
Физический движок не используется: игрок — круг радиуса 0.3 в плоскости XZ,
стены — прямоугольники, движение разрешается раздельно по осям (это даёт
скольжение вдоль стены). Sweep не нужен: при 3 м/с и кадре 16 мс смещение 5 см.
Текстурных файлов нет; пространство читается за счёт цвета комнат, рёбер и
процедурных шейдеров. Надпись EXIT рисуется canvas-текстурой в рантайме.

## Команды

`package.json` ещё не создан. Планируемый набор:

```
npm run dev              # Vite dev-сервер
npm run dev -- --host    # то же, но доступно с телефона по локальной сети
npm run build            # продакшен-сборка в dist/
npm test                 # весь Vitest
npm test src/core/collision.test.ts   # один файл тестов
```

Отладка тач-управления делается **только на реальном телефоне** через `--host`.
DevTools врёт про инерцию, мультитач и размер пальца.

## Главное правило архитектуры

**`src/core/` не импортирует three.js. Никогда.**

Проект делится на два слоя с жёсткой границей:

- **`core/`** — чистый TypeScript: типы и валидация уровня, состояние мира
  (что заперто, что подобрано, какие флаги взведены), инвентарь, реестр
  взаимодействий, генерация коллайдеров и математика коллизий. Всё покрыто тестами,
  запускается без браузера и WebGL.
- **`render/`** — three.js: строит сцену из уровня, анимирует двери, рисует предмет
  в руках второй камерой с малым near-plane (иначе он протыкает стены).
  Читает состояние из `core`, отправляет туда команды, подписывается на события.

Между ними — **`input/`**, прячущий разницу между «pointer lock + WASD» и
«виртуальный стик + свайп» за одним интерфейсом. Остальной код не должен знать,
с какого устройства играют.

Инвентарь и HUD — **DOM-оверлей, не 3D**. Это бесплатно даёт тач-скролл, нормальные
шрифты и кнопки нужного размера под палец.

Если тянет дёрнуть меш напрямую из игровой логики — значит граница нарушается,
и это надо решать иначе.

## Взаимодействия — только данными

«Ключ на замок» — частный случай матрицы взаимодействий. Хардкод вида
`if (item === 'key' && target === 'lock')` запрещён. Правила живут в реестре:

```json
{ "use": "key_brass", "on": "lock_front",
  "effects": [{"destroy": "lock_front"}, {"consume": "key_brass"}, {"sound": "unlock"}] }
```

Добавление нового предмета должно быть правкой данных, а не кода.

## Формат уровня

Уровни пишутся руками в JSON: комнаты — прямоугольники `[x, z, w, d]` на сетке 1 м,
двери задаются парой соединяемых комнат и точкой на общей стене (ориентация выводится
автоматически). Коридор — это не отдельная сущность, а узкая комната.

Из одних и тех же данных генерируются и геометрия, и коллайдеры. Стена с дверью
режется не CSG, а тремя прямоугольниками: слева, справа и перемычка сверху.

`validateLevel()` обязана ловить опечатки автора карты (дверь ссылается на
несуществующую комнату, замок без ключа на уровне, наложение комнат) и показывать
внятные ошибки вместо запуска игры.

Единицы — метры. Игрок: рост 1.7, глаза 1.6, радиус капсулы 0.3. Комнаты высотой 3.0,
стены 0.2, дверной проём 0.9 × 2.1. Все константы — в `src/config.ts`.

## Жёсткие ограничения среды

- **GitHub Pages не отдаёт кастомные HTTP-заголовки** → нет COOP/COEP → нет
  `SharedArrayBuffer`. Всё, что требует потоков, использовать нельзя.
- `vite.config.ts` обязан содержать `base: '/bandy/'`, иначе на Pages белый экран
  и 404 на все ресурсы.
- ES-модули не работают по `file://`. Открывать только через dev-сервер.
- **На iPhone Safari нет Fullscreen API.** Ландшафт не залочить, адресная строка
  съедает экран. Обход — PWA (`display: standalone`).
- **Pointer Lock не существует на мобильных**, hover тоже. Подсветка цели работает
  через центральный прицел, а не через курсор.
- Мобильные GPU плохо переносят realtime-тени и большое число draw call'ов.
- После сворачивания вкладки `deltaTime` приходит в секундах и телепортирует
  игрока сквозь стены. dt всегда клампится (~50 мс), `visibilitychange` ставит паузу.

## Соглашения

- Хоткеи читаются **только через `event.code`** (физическая клавиша), никогда через
  `event.key` — иначе игра ломается при смене раскладки. Инвентарь: `KeyI` и `Tab`.
- Освещение задаётся покомнатно в JSON уровня. В первой версии свет ровный, но
  значение — множитель, чтобы позже добавить полумрак и фонарик без правки рендера.
